# Changelog — RevOps Firefighter

- **v1** — Logic only, colored rectangles. Random non-overlapping reachable server placement, OK/BURNING/BURNED_DOWN state machine, escalating random ignition, burn-down timer, hold-SPACE-to-extinguish with progress bar, arrow-key movement with wall clamping, win/lose conditions, R to restart, debug text overlay.
- **v2** — Textured walls (border + 2 partition pillars) and 4 fixed desk obstacles the player collides with and servers avoid; main menu screen (Start/Exit wired up, Change Map + mute stubbed in disabled); brand palette + pixel-font stats HUD panel replacing the raw debug text; separate "X/3 SERVERS LOST" danger meter with a pulsing warning border; point system (+100 extinguish, -150 per server lost, +1/sec survived) with an in-memory top-5 session leaderboard shown on the end screen. All new textures (wall/floor/desk/HUD-frame/badge/menu-background) degrade to plain brand-colored shapes until the real PNGs are dropped into `/assets/images/`.
- **v3** — Server rack sprite (grayscale+darken filter for BURNED_DOWN) with an animated 8-frame fire overlay on BURNING servers; 4-direction player walk-cycle sprite (idle pose when not moving); looping muted autoplay background video on the main menu, falling back to the static wash image; Escape pause menu (Continue / Quit-to-menu) with a randomly-picked, non-repeating taunt line next to Quit. All new sprites/video degrade to the previous flat-shape rendering until dropped into `/assets/sprites/` and `/assets/video/`.
- **v3.1** — Map Select screen: "Start Game" now opens a 4-map picker (Open Floor/Easy, Cubicle Rows/Medium, Server Ring/Medium, Maze Grid/Hard) instead of starting straight into a run, each card showing a live schematic preview plus a difficulty badge and one-line description. The old disabled "Change Map" stub button on the main menu is removed — picking a layout is now just step two of starting any new game, including after Quit-to-menu. Under the hood, the fixed desk/partition layout moved out of `CONFIG` into a `MAPS` array, with `buildMapLayout()` computing the wall/desk/collision data for whichever map was picked.
- **v4** — `BURN_DOWN_TIME` doubled (8s -> 16s) so fires are less punishing to reach in time. Scoring simplified to a single rule: +1 per successful extinguish, no time bonus or burn-down penalty. New "Shantanu" boss event: once score reaches 10, a repeating 30s timer (frozen during pause) has him walk in from a random map edge on his own walk-cycle sprite, show a 2s speech bubble ("I have BAD SHANTANEWS for you!"), force-ignite one random OK server, then walk back out — modeled as its own `IDLE -> ENTERING -> TALKING -> WALKING_TO_TARGET -> IGNITING -> LEAVING` state machine that runs alongside normal gameplay (only his own movement pauses during the bubble). Skips the event cleanly if no OK servers are available, and only ever runs one instance at a time.
- **v4.1** — Removed leftover debug output from the Shantanu event (the `SHANTANU: <state>` label drawn under him, plus two `console.log` calls) — purely a cleanup, no behavior change. Map-select cards now preview each layout with the real floor/wall/desk sprites and the player's idle sprite at spawn, instead of flat placeholder rectangles, degrading to the old flat-color preview if those PNGs aren't loaded yet (same convention as the in-game rendering).
- **v4.2** — Main menu background swapped from a looping mp4 video to a looping GIF (`assets/video/MainPage_VideoOneTime.gif`). Rendered as a plain `<img>` instead of `<video>`, so it just animates/loops on its own — no autoplay/muted/playsinline attributes or JS play()/pause() calls needed anymore.
- **v5** — `walking_sprite_v2.png` replaces the v3 player sheet (new 248x283 cell size, fixes the walk-cycle "jump" from the old sheet's uneven frame cropping); `burned_server_rack.png` replaces the grayscale-filter trick for BURNED_DOWN servers. Gameplay music (looping) starts on Start Game, pauses on win/lose/pause-menu, resumes on Continue; Shantanu plays a one-shot alarm exactly once per event, right as he enters — both now gated by a real mute button (was a disabled stub through v4). Player and Shantanu are both rendered twice as big (`PLAYER_SPRITE_W` 40->80, hitbox `PLAYER_SIZE` 24->48 to match, same ratio as before; Shantanu's drawn size now just mirrors the player's instead of its own constant). Layout: the stats panel moved off the game canvas onto its own bigger, centered side panel to the right; a new static controls/how-to-play panel sits under the canvas — both reuse `stat_panel_frame.png` and are their own `<canvas>` elements alongside the main one. The old inline "arrow keys / space / esc / R" hint text is retired in favor of the new controls panel.
- **v9** — Grid grown ~30% (`COLS` 20->26, `ROWS` 14->18, canvas 800x560 -> 1040x720; `TILE` unchanged at 40px, so every sprite stays the same size). This gives servers' actual rendered sprite boxes enough room to satisfy v8's wall-clearance and server-overlap checks on **every** map — including Cubicle Rows and Maze Grid, which previously failed 100% of the time and showed zero servers — without changing any map's desk/partition layout (simulation-verified: all 4 maps now place all 10 servers 100% of the time, both v8 rules kept exactly as they were). The stats panel and controls panel now size themselves — pixel dimensions and internal font sizes/line spacing alike — from the main canvas (`STATS_PANEL_SCALE`/`CONTROLS_PANEL_SCALE`) instead of fixed constants, so they scale with any future grid resize automatically instead of needing to be hand-updated in a separate file. Every map's desk/partition tiles are also shifted `(+3 cols, +2 rows)` — exactly how much the grid grew on each side — so each layout stays centered in the bigger room with an even margin on all four sides, instead of pinned to the old room's position in its new top-left corner with all the extra floor piling up unevenly on the right/bottom. Pure repositioning only: no desk, wall, or partition changed size, and simulation confirms all 4 maps still place all 10 servers 100% of the time after the shift.
- **v10** — The top-5 leaderboard now persists to `localStorage` (`revopsFirefighter.leaderboard`) instead of resetting on every reload — it's read back on page load and re-saved every time a run ends. Per-browser/per-device only (this is client-side storage, not a shared server-side database), so it's scoped the same way any other site's "remember me on this device" data is. End-screen label updated from "TOP 5 THIS SESSION" to "TOP 5 BEST SCORES" to match. Falls back to an empty leaderboard (rather than erroring) if storage is unavailable — private-browsing mode, storage disabled, or corrupted data.
